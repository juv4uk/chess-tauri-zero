# Перенесення на PyTorch 2.13 (українська документація)

**Дата:** 2026-08-26

## Навіщо

Оригінальний проєкт закріплений на `tensorflow-gpu==1.15.2` і
`keras==2.0.8` — стек з 2017-2019 років. На сучасній машині (Python
3.12) це реальний глухий кут:

- PyPI більше не роздає wheel-пакет `tensorflow-gpu` для Python 3.12
  (лишилась лише версія 2.12.0, під зовсім іншу назву пакета в новіших
  релізах).
- Guix теж прибрав Python 3.6/3.7 зі свого каналу пакетів — немає
  звідки взяти сумісну версію.

Реальна натренована модель (`data/model/model_best_weight.h5` +
`model_best_config.json`) при цьому нікуди не поділась — тож
розв'язок: переписати саму архітектуру мережі на PyTorch і перенести
вже готові ваги, а не тренувати щось із нуля.

## Що додано

- **`src/chess_zero/agent/torch_model.py`** — `ChessResNet`, точна
  архітектура: вхідна `Conv2D(18→256, 3×3, без bias)` + BatchNorm +
  ReLU, 7 residual-блоків (256 фільтрів, 3×3), голова політики (conv
  256→2, 1×1 + BN + ReLU + `Linear(128, 1968)` + softmax), голова
  оцінки позиції (conv 256→**1**, 1×1 + BN + ReLU + `Linear(64, 256)`
  + ReLU + `Linear(256, 1)` + tanh).

  Архітектуру звірено напряму проти реального
  `model_best_config.json`, а не вгадано з коду `model_chess.py` —
  зокрема, кількість фільтрів у голові оцінки виявилась **1**, а не
  4, як спершу здавалось із загального опису в оригінальному коді.
  Реальна форма ваг у H5-файлі — єдине надійне джерело правди тут.

- **`src/chess_zero/agent/load_weights.py`** — переносить реальні ваги
  з Keras H5-файлу в PyTorch-модель. Головні технічні нюанси:
  - Keras зберігає ядро `Conv2D` як `(kh, kw, in_ch, out_ch)`, PyTorch
    очікує `(out_ch, in_ch, kh, kw)` — переставлено `(3, 2, 0, 1)`.
  - Keras `Dense`-ядро — `(вхід, вихід)`, PyTorch `Linear` —
    `(вихід, вхід)` — транспоновано.
  - `BatchNormalization`'s `gamma`/`beta`/`moving_mean`/
    `moving_variance` мапляться напряму на PyTorch's
    `weight`/`bias`/`running_mean`/`running_var`, без перетворень.

- **`src/chess_zero/agent/play_torch.py`** — мінімальний inference:
  бере позицію, кодує її тим самим `canon_input_planes()` з
  `chess_env.py` (той файл — чистий numpy + python-chess, без Keras/TF
  узагалі, тому перенесення не знадобилось), пропускає крізь модель,
  вибирає хід жадібно за головою політики (**без MCTS** — оригінал
  використовував 1200 симуляцій MCTS на хід; тут лише перевірка, що
  порт коректний).

## Перевірка (не просто "код компілюється")

На стартовій позиції модель впевнено обирає **c2c4** (Англійський
дебют, реальний, визнаний дебют) з імовірністю 99.59%, e2e4/d2d4 теж у
топ-5, оцінка позиції ~0 (збалансовано, як і очікується для першого
ходу). Якби перенесення ваг мало помилку в перестановці/транспонуванні
— вийшов би хаотичний, не-шаховий результат, а не впізнаваний дебют.
Це і є доказ коректності порту, не лише відсутність винятків під час
завантаження.

## Запуск

```bash
cd chess-tauri-zero
python3 -m venv .venv
.venv/bin/pip install torch h5py numpy python-chess
cd src
../.venv/bin/python3 chess_zero/agent/play_torch.py
```

## Що НЕ зроблено

- MCTS (пошук по дереву) не перенесено — жадібний вибір ходу набагато
  слабший за силу гри оригінального проєкту.
- Повний UCI-інтерфейс (`play_game/uci.py`) не адаптовано під новий
  `ChessResNet` — використано лише прямий Python-виклик.
- Тренування (`Coach.py`, self-play) не перевірялось на сумісність —
  лише inference з уже готовими вагами.
