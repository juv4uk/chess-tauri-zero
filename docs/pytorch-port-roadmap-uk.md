# План: довести PyTorch-порт до повноцінного руху

**Дата:** 2026-08-26 · База: `docs/pytorch-port-uk.md` (що вже зроблено)

Порядок — за реальною цінністю: MCTS першим (найбільший приріст сили
за найменші зусилля, і сама логіка вже не залежить від Keras/TF), решта — за спаданням пріоритету.

## 1. MCTS (пошук по дереву) — найвищий пріоритет

**Реальна знахідка з прочитання коду:** `player_chess.py` (370 рядків,
клас `ChessPlayer`) — це вже чистий Python/numpy: дерево пошуку
(`VisitStats`/`ActionStats`), формула PUCT (`select_action_q_and_u`),
Dirichlet-шум у корені, температурний вибір фінального ходу. **Єдине
місце, що торкається моделі** — метод `predict()`, який зараз шле
дані через `multiprocessing`-канал (pipe) до окремого Keras-процесу
(`ChessModelAPI`, потрібно було для TF1's session-based
багатопоточності).

**Що робити:**
1. Скопіювати `player_chess.py` в новий файл (`player_chess_torch.py`
   або адаптувати на місці) без змін до самого дерева/формул.
2. Замінити `predict()` — замість pipe, прямий виклик
   `torch_model(state_planes)` під `torch.no_grad()`. PyTorch
   inference за замовчуванням thread-safe для forward-проходу без
   градієнтів, тож `ThreadPoolExecutor` (`search_threads`) можна
   лишити як є, спробувати без змін спершу.
3. `expand_and_evaluate`/`calc_policy`/`apply_temperature` — не
   чіпати, вони вже model-агностичні.
4. Перевірка: та сама стартова позиція, `simulation_num_per_move`
   зменшити з 1200 до, скажімо, 100-200 для швидкої перевірки —
   порівняти, чи топ-хід лишається розумним (не обов'язково той
   самий, що жадібний вибір, MCTS може знайти щось глибше).

**Оцінка зусиль:** невелика-середня. Логіка вже написана й не
залежить від TF — головний ризик суто в конкурентному доступі
PyTorch-моделі з кількох потоків, перевіряється швидко.

## 2. UCI-інтерфейс

`play_game/uci.py` (вже переглянутий) — простий stdin/stdout цикл,
команди `uci`/`isready`/`position`/`go`, викликає `ChessPlayer`.
Після кроку 1 (MCTS-порт) це майже "підключи новий ChessPlayer
замість старого" — сам протокол не залежить від TF/Keras.

**Що робити:**
1. Дочекатись кроку 1.
2. У `uci.py` замінити інстанціювання моделі/плеєра на PyTorch-версії.
3. Перевірити через реальний GUI (Arena/CuteChess/`python-chess`'s
   `chess.engine.SimpleEngine.popen_uci`) — підключити як звичайний
   рушій і зіграти партію.

**Оцінка зусиль:** мала, після кроку 1.

## 3. Тренування / self-play (Coach-аналоги)

`worker/self_play.py`, `worker/sl.py` (supervised learning),
`worker/optimize.py`, `worker/evaluate.py` — усі напряму залежать від
Keras `Model.fit`/`compile`, оптимізаторів, callback'ів. Це вже не
проста заміна виклику, а реальне переписування тренувального циклу
на PyTorch (`torch.optim`, власний training loop або `Lightning`).

**Що робити (якщо колись знадобиться):**
1. `self_play.py`: генерація партій через MCTS (з кроку 1) — портується
   майже безкоштовно, якщо крок 1 готовий.
2. `optimize.py`: переписати цикл навчання — реальна робота, включно
   з відтворенням функції втрат AlphaZero (policy cross-entropy +
   value MSE + L2), точно узгодженою з оригіналом.
3. `evaluate.py`: порівняння двох моделей одна проти одної — легко
   переноситься, це просто `self_play`-подібні партії двох гравців.

**Оцінка зусиль:** велика. Це вже не "порт", а окремий проєкт —
робити тільки якщо реально захочеться дотренувати модель, не заради
самої повноти.

## 4. Розподілене навчання через FTP

`model_chess.py`'s `distributed`-режим — FTP-сервер з коду 2017-го
(`alpha-chess-zero.mygamesonline.org`), майже напевно мертвий.

**Рекомендація:** не відновлювати. Якщо колись знадобиться ділитись
вагами між машинами — простіше зробити через git LFS чи звичайний
S3/HTTP, ніж воскрешати FTP з паролем у відкритому коді.

## Підсумок пріоритету

| Крок | Цінність | Зусилля | Залежить від Keras/TF |
|---|---|---|---|
| 1. MCTS | висока (сила гри) | мала-середня | ні (лише через predict()) |
| 2. UCI | середня (зручність) | мала, після (1) | ні |
| 3. Тренування | низька зараз | велика | так, повне переписування |
| 4. FTP-розподіл | немає | — | не відновлювати |
