# release/ — завжди поточні бінарники

На відміну від [GitHub Releases](https://github.com/juv4uk/chess-tauri-zero/releases)
(версіоновані знімки — v0.0.1, v0.0.2, ...), файли тут **перезаписуються
на кожен реліз-вартий пуш** і завжди відповідають останньому коміту
`master`. Не версіоновані іменем файлу навмисно — версія вшита прямо
в сам бінарник (видно в заголовку вікна при запуску: `Chess Tauri
Zero vX.Y.Z`, береться з `app/src-tauri/tauri.conf.json`, не хардкод).

| Файл | Платформа |
|---|---|
| `chess-tauri-zero-current-linux-x86_64` | Linux, `x86_64-unknown-linux-gnu` |
| `chess-tauri-zero-current-windows-x86_64.exe` | Windows, `x86_64-pc-windows-gnu` (крос-компільовано) |

## Як реально запускати (важливо!)

**Не запускай бінарник напряму подвійним кліком чи з цієї теки.**
Реальний, знайдений і перевірений баг: `tauri.conf.json`'s
`"frontendDist": "../web"` резолвиться відносно **робочої директорії
(CWD) на момент запуску**, а не відносно того, де фізично лежить сам
файл (`bundle.active` — `false`, тобто нічого не вшито в бінарник).
Якщо запустити файл із цієї теки (чи подвійним кліком у Windows
Provider, де CWD = тека самого `.exe`) — процес стартує, але вікно
**не з'являється взагалі, без жодної помилки**, бо фронтенд-файли не
знаходяться. Перевірено напряму: той самий бінарник відкриває вікно
коректно лише коли CWD = `app/src-tauri/`.

Тому користуйся обгортками, а не самими бінарниками:

```bash
# Linux
./release/run-linux.sh
```
```powershell
# Windows
release\run-windows.bat
```

Обидва скрипти самі переходять у правильну директорію
(`app/src-tauri/`) перед запуском бінарника — працює з будь-якого
місця, звідки їх викликати (перевірено напряму: запуск з `/tmp`
на dev-машині відкрив вікно коректно).

Обидва — portable-бінарники без Python усередині: клонуй репо,
налаштуй `.venv` за `readme.md` (venv/`src/` мають лишатись поруч із
репозиторієм — sidecar шукає їх відносно `app/src-tauri/binaries/`).

**Хто оновлює:** щоразу, коли є реліз-вартий набір змін (не кожен
дрібний коміт з документацією) — перебілдити обидва (`cargo build
--release` + крос-компіляція під Windows, див.
`docs/tauri-app-uk.md`), скопіювати сюди з новими іменами (`current-*`,
без зміни назви), закомітити разом зі змінами коду в тому ж пуші.
